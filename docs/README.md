# 文档索引

代码在 `app/`，判断在 [`README.md`](../README.md)，**过程在这里**。

`docs/` 里的十份文件不是同一批产出，读的顺序有讲究：先看需求从哪来，再看设计画在哪，
最后看做没做到。按这个顺序走，每份文档都能回答上一个留下的问题。

## 一、需求从哪来

| 文件 | 规模 | 是什么 | 该看哪几节 |
|---|---|---|---|
| [`discovery-report.md`](./discovery-report.md) | 326 行 | 业务发现报告：从"群里喊一声"到 R01–R08 的推导过程 | **证据缺口**、访谈记录、需求如何归纳 |
| [`同行方案-共享设备预约与维护.md`](./同行方案-共享设备预约与维护.md) | 232 行 | 6 个开源案例的对比调研 | 总览对比表、按需求映射、风险与注意事项 |
| [`现状流程图.png`](./现状流程图.png) | 图示 | As-Is 流程：一次借用现在要经过谁 | 全图 |
| [`一页纸需求清单-MVP-v1.md`](./一页纸需求清单-MVP-v1.md) | 91 行 | 需求基线：R01–R08 与验收口径 | 五、功能需求；七、明确不做（附回头条件） |
| [`访谈记录-顾明岚-实验平台主任.docx`](./访谈记录-顾明岚-实验平台主任.docx) | 2 页 | 第 10 轮访谈原文：平台层面只有两项可确认量化 | 边界声明、量化缺口、后续动作 |

这份发现报告里有一节叫 **证据缺口**，写明"哪些结论没有一手访谈支撑"。
留着它是有意的：评审最容易问"你这些结论哪来的"，把缺口先说了，比被问出来强。

那份访谈记录就是补这条缺口的**原始材料**，它自己也承认了缺口：受访者只管业务目标与
试点决策，不经手借设备，所以"一次具体借设备经历"没有可核实的事实；平台层面能确认的
只有有效使用率 51%（目标 68%）与爽约率 16%（目标 6%）两项，六个流程节点各自的
等待与处理时间**管理层尚未分别量化**。这条"没有数字"本身就是结论——它解释了为什么
后续设计只能提假设，而不能声称已验证。

## 二、口径变了怎么办

需求基线（`一页纸需求清单`）写的是 **4 张表，不许多**；实现是 **13 张**。

这不是失控，每一张表都对应一条需求，逐条理由写在
[README「数据模型」](../README.md#数据模型)那一节。同类变化还有三处口径，
集中在 [`需求追溯.md`](./需求追溯.md) 的**附录 B：待确认的三处口径**。

改动本身不是问题，**改动没有记录**才是问题。

## 四、做没做到

| 文件 | 回答什么问题 |
|---|---|
| [`需求追溯.md`](./需求追溯.md) | R01–R08 每条的实现位置、测试名、可核对证据、**没做到的部分** |
| [`检索评测.md`](./检索评测.md) | 检索到底准不准：20 条问题 × 三路对照，Hit@3 与 MRR，错在哪一题 |
| [`../README.md`](../README.md#测试) 测试节 | 130 项用例分六组，各覆盖什么风险 |
| [`../scripts/verify.py`](../scripts/verify.py) | 一条命令把"测试通过"翻译成"需求 X 有证据" |

`verify.py` 输出的 PASS 只代表**工具侧可核对**，不代表业务验收通过。
这条免责声明写在脚本里，也写在 README 里——它能防止把一张自检表当成验收单。

## 五、语料

[`manuals/设备借用制度-v1.md`](./manuals/设备借用制度-v1.md) 是 RAG 的唯一语料，
六章、约 2400 字，够回答"能约几格""超期怎么办""能不能转借"这类问题。

真实项目里语料会膨胀到几百份，那时需要的是切分策略与评测集，不是更大的模型。
本项目的取舍见 [README「语料」](../README.md#语料)。

## 附：不参与评审的材料

以下两份放在 `docs/` 里是为了保留来源，**不是本项目的交付物**：

- `research-equipment-fde-training.md`（1096 行）：课程题目与方法论提纲，
  从业务挖掘到运营迭代的九段式。项目的调研动作是照这份提纲做的，但它本身不是产出。
- `AI智能体项目报价单_基础费+效果浮动.xlsx`：商务报价模板（5 个工作表：
  报价单、效果浮动、交付清单、参数、成本测算）。留作参考，与系统实现无关。
- `AI智能体项目分档报价单.docx`：由上面那份 xlsx 改出的三档（轻量/标准/深度）
  商务报价单，含条款编号、浮动计量规则与签署区。同样是商务材料，不属于系统交付物；
  三档的人天与金额在同一套成本参数下逐科目重算，分项取整合计可对得上。

把这两份和交付物混在一起放，会让"这个仓库到底交付了什么"变得不清楚，
所以单独列出来。
